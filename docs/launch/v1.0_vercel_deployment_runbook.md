# v1.0 코인미러 Vercel 배포 런북

- 기준일: 2026-09-21
- 대상: Free Public MVP Preview/Production 배포
- 배포 방식: Expo Router `web.output: "server"` + Vercel Node Function adapter
- 원칙: 원본 PDF/CSV, PDF 비밀번호, 종목명, 금액, 수량, 수익률, 원본 파일명은 Vercel 로그/Analytics/AI 요청에 남기지 않는다.

## 1. 왜 static-only 배포가 아닌가

코인미러는 정적 Expo Web만 사용하는 앱이 아니다.

- 클라이언트: `dist/client`
- 서버 번들: `dist/server`
- same-origin API: `/api/ai-reflection`, `/api/market-context`, `/api/exchange-events`
- 서버 전용 환경변수: `COINMIRROR_AI_REFLECTION_OPENAI_API_KEY`

따라서 Vercel에서는 `dist/client`만 서빙하는 설정이 아니라 `expo-server/adapter/vercel`을 통해 Expo server output을 함께 연결해야 한다.

## 2. 저장소 배포 계약

필수 파일:

- `vercel.json`
- `api/index.ts`
- `src/app/api/ai-reflection+api.ts`
- `src/app/api/market-context+api.ts`
- `src/app/api/exchange-events+api.ts`
- `app.json`의 `expo.web.output: "server"`

`vercel.json`은 다음 계약을 유지한다.

```json
{
  "buildCommand": "npx expo export -p web",
  "outputDirectory": "dist/client",
  "functions": {
    "api/index.ts": {
      "includeFiles": "dist/server/**"
    }
  },
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/api/index"
    }
  ]
}
```

`api/index.ts`는 Expo server bundle을 Vercel function으로 연결한다. `api/*.ts`는 프로젝트의 Node.js 24.x runtime을 자동 사용하므로 `@vercel/node` builder 버전을 `vercel.json`에 고정하지 않는다. 이 파일에는 secret 이름이나 값, `EXPO_PUBLIC_*` AI key를 넣지 않는다.

## 3. Vercel 프로젝트 생성

1. Vercel Dashboard에서 GitHub 저장소 `jeus0519/coinmirror`를 import한다.
2. Framework preset은 자동 감지 또는 Other를 사용한다.
3. `vercel.json`이 build command와 output directory를 통제하므로 Dashboard 설정은 코드와 충돌하지 않게 둔다.
4. Node.js version은 Vercel 지원 기준 `24.x`를 사용한다. 현재 `package.json`의 `engines.node`는 Vercel의 24.x 런타임과 호환된다.

## 4. 환경변수

Vercel Project Settings → Environment Variables에서 Preview부터 등록한다.

| 변수명 | 환경 | 용도 | 주의 |
|---|---|---|---|
| `COINMIRROR_AI_REFLECTION_OPENAI_API_KEY` | Preview | AI 행동코칭 서버 호출 | 값은 절대 문서/로그/채팅에 복사하지 않는다 |
| `COINMIRROR_AI_REFLECTION_OPENAI_API_KEY` | Production | 공개 배포 후 AI 행동코칭 | Preview 검증 전 Production 등록/사용 보류 |

현재 fallback-only 런칭에서는 AI key를 등록하지 않는다. abuse 방어는 path·method 조건을 가진 Vercel edge WAF rule이 함수 실행 전에 적용하므로 `COINMIRROR_AI_REFLECTION_RATE_LIMIT_ID`도 등록하지 않는다. route의 `@vercel/firewall` SDK hook은 향후 코드 내부 조건이 필요한 경우에만 사용하며, 직접 edge rule과 동시에 활성화해 이중 카운트하지 않는다.

금지:

- `EXPO_PUBLIC_COINMIRROR_AI_REFLECTION_OPENAI_API_KEY`
- `NEXT_PUBLIC_*` 형태의 AI secret
- `.env` 커밋
- build log 또는 runtime log에 key 값 출력


## 5. AI abuse 방어 설정

### 5.1 클라이언트 호출 제한

분석 결과 화면의 `AI 행동코칭 받기`는 다음 정책을 사용한다.

- 검증된 원격 AI 응답이 성공한 경우에만 해당 분석 fingerprint를 최종 잠근다.
- timeout, HTTP/JSON/schema 오류, `source=fallback`은 실패로 처리하고 로컬 기본 행동코칭을 유지한다.
- 최초 요청 실패 후 30초 쿨다운을 적용하며 버튼에 남은 시간을 표시한다.
- 쿨다운 종료 후 최대 3회 재시도할 수 있다. 즉, 최초 요청 1회와 재시도 3회를 합쳐 총 최대 4회다.
- 네 번째 실패 후에는 해당 분석에서 추가 요청을 막는다. 처음 보는 새 fingerprint는 별도 상태로 시작하며, 같은 fingerprint로 돌아오면 기존 성공 잠금·실패 횟수·쿨다운을 유지한다.
- 측정 가능한 행동 지표나 분석 fingerprint가 없어 API를 호출하지 않은 경우는 실패 횟수에 포함하지 않는다.

이 제한은 UX와 불필요한 중복 요청 방지용이다. 실제 abuse 방어 경계는 아래 Vercel WAF rate limit이다.

### 5.2 Vercel WAF rate limit

현재 공개 MVP는 Vercel edge WAF에서 path와 method를 직접 검사한다. 함수 호출 전에 차단되므로 provider key 유무와 무관하게 abuse 방어 경계로 동작한다.

권장 초기값:

- 대상 path: `/api/ai-reflection`
- method: `POST`
- counting key: IP
- strategy: Fixed Window
- window: 60초
- limit: 10 requests
- action: 429 Rate Limit

30초 클라이언트 쿨다운에서 정상 사용자 1명의 최대 요청은 분당 약 2회다. 10회는 같은 공유 IP에서 약 5명이 동시에 최초 요청과 재시도를 수행할 여유를 주면서 자동 반복 호출을 제한한다. 실제 AI provider를 활성화할 때는 비용·공유 IP 오탐 데이터를 확인한 뒤 5회로 강화하는 방안을 우선 검토한다.

Vercel 공식 기준으로 Hobby는 프로젝트당 rate-limit rule 1개와 월 1,000,000 allowed requests가 포함된다. Pro는 지역별로 1,000,000 allowed requests당 $0.50부터 시작한다. rate-limit 카운터는 region별이므로 여러 region으로 분산된 동일 key 트래픽은 설정값을 초과할 수 있다.

Vercel Dashboard 절차:

1. Project → Firewall → Configure → New Rule
2. rule 이름: `Coinmirror AI reflection rate limit`
3. 조건: path equals `/api/ai-reflection`, method equals `POST`
4. Then: Rate Limit, Fixed Window, 60초 / 10 requests, key: IP
5. Save Rule → Review Changes → Publish
6. 직접 edge rule에서는 SDK rule ID 환경변수를 등록하지 않는다.
7. Preview에서 과다 호출 시 Vercel WAF가 HTTP 429와 `Too Many Requests` 오류 JSON을 반환하는지 확인한다.

2026-09-23 live rule publish 후 합성 `{}` POST 14건을 병렬 호출해 HTTP 400 10건과 WAF HTTP 429 4건을 확인했다. WAF 429는 함수의 `{ ok: false, error: "rate_limited" }`가 아니라 Vercel edge의 generic error JSON이며, 정상 앱 함수가 실행되기 전에 반환된다.

## 7. Preview 배포 후 필수 검증

Preview URL을 `<preview-url>`로 둔다.

### 7.1 화면 검증

- 랜딩 페이지가 정상 렌더링된다.
- `현재는 업비트 PDF/CSV를 먼저 지원해요` 문구가 보인다.
- 업로드 화면이 정상 진입된다.
- 분석 결과 화면에서 `AI 행동코칭 받기` 버튼이 보인다.
- AI 실패 시 `AI 행동코칭을 불러오지 못했어요.` 안내와 기본 회고 카드가 유지된다.
- 실패 후 버튼에 30초 카운트다운이 보이고, 종료 후 최대 3회 재시도할 수 있다.
- 검증된 AI 응답 성공 후에는 같은 fingerprint의 버튼이 완료 상태로 잠긴다.

### 7.2 API 계약 검증

#### `/api/ai-reflection`

다음을 확인한다.

- 잘못된 schema → HTTP 400
- malformed JSON → HTTP 400 `invalid_request`
- 2,048 bytes 초과 body → HTTP 413
- 유효 safe payload + AI key 미등록/비정상 → HTTP 200 fallback 또는 안전 실패 후 클라이언트 기본 행동코칭
- 유효 safe payload + AI key 정상 → HTTP 200, `source: "ai"` 가능
- 응답에 `Cache-Control: no-store` 유지

#### `/api/market-context`

- HTTP 200과 `live` 또는 안전한 `fallback` 상태를 반환한다.
- BTC·ETH·XRP를 기본 표시하고, 세 자산을 제외한 최근 24시간 업비트 KRW 거래대금 상위 3개를 추가한다.
- 각 자산의 전체 KRW 거래대금 대비 비중을 표시한다.
- 브라우저가 업비트·Alternative.me를 직접 호출하지 않고 same-origin API만 호출한다.

#### `/api/exchange-events`

- HTTP 200과 `live` 또는 안전한 `fallback` 상태를 반환한다.
- 업비트·빗썸 이벤트를 각각 최대 3개와 거래소 링크로 제공한다.
- 외부 페이지 구조 변경이나 빈 provider 결과에서 앱 전체 오류 대신 fallback으로 전환한다.
- 브라우저가 거래소 페이지를 직접 호출하지 않고 same-origin API만 호출한다.

검증 payload에는 실제 종목명, 금액, 수량, 수익률, 원본 파일명, PDF 비밀번호를 넣지 않는다. 합성 safe payload만 사용한다.

## 9. Rollback

문제가 있으면 다음 순서로 대응한다.

1. Vercel Dashboard에서 직전 정상 deployment로 rollback 또는 alias 재지정.
2. AI key 관련 문제가 의심되면 Vercel 환경변수에서 key 제거/회전.
3. 로그에 민감정보가 남은 정황이 있으면 해당 key 폐기, 로그 보존 범위 확인, 원인 코드 수정 전까지 공개 중단.
4. GitHub에는 수정 커밋을 별도로 남긴다. force push 금지.

## 10. 비차단 후속 과제

- 공개 범위 확대 전 WAF rate limit 임계값을 실제 트래픽 기준으로 조정
