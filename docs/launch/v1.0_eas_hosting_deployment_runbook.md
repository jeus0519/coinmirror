# v1.0 코인미러 EAS Hosting 배포 런북

- **기준일:** 2026-09-09
- **상태:** 외부 배포 승인 전 실행 준비
- **목적:** Expo Router 웹과 `/api/ai-reflection`을 같은 origin에서 배포하고, AI 비밀정보·개인정보·장애 fallback을 검증한다.
- **공식 근거:**
  - Expo Router API Routes: https://docs.expo.dev/router/web/api-routes
  - EAS Hosting 시작: https://docs.expo.dev/eas/hosting/get-started
  - EAS Hosting API Route 관찰: https://docs.expo.dev/eas/hosting/api-routes

> 이 문서는 명령과 변수명만 기록한다. API 키·토큰·인증 쿠키·계정 식별값은 문서, Git, 채팅, 로그에 저장하지 않는다.

## 1. 현재 배포 계약

- `app.json`의 `expo.web.output`: `server`
- API Route: `src/app/api/ai-reflection+api.ts`
- 재사용 handler: `api/ai-reflection.ts`
- 클라이언트 경로: same-origin `/api/ai-reflection`
- 서버 전용 환경변수: `COINMIRROR_AI_REFLECTION_OPENAI_API_KEY`
- 클라이언트에 금지: `EXPO_PUBLIC_*` 이름의 AI key/token/secret

## 2. 로컬 Pre-flight

```bash
npm test
npm run lint
npm run typecheck
git diff --check
npx expo export --platform web
```

확인 항목:

- [ ] `dist/`에 웹 client와 server 산출물이 존재한다.
- [ ] server manifest에 `/api/ai-reflection` 경로가 포함된다.
- [ ] safe payload는 200 또는 의도한 deterministic fallback을 반환한다.
- [ ] invalid/extra-field payload는 400을 반환한다.
- [ ] 2,048 UTF-8 bytes 초과 payload는 413을 반환한다.
- [ ] AI key가 없을 때 외부 모델 호출 없이 기본 코칭으로 종료된다.
- [ ] timeout/network/malformed response에서 화면 로딩이 끝나고 기본 코칭을 표시한다.

- [ ] 서버 환경변수를 EAS secret/environment로 등록할 담당자 확정
- [ ] AI provider 비용 상한·요청 제한 결정

- [ ] 이해충돌/겸업 검토 전 결제·유료 홍보를 하지 않기로 확인

## 4. 승인 후 Preview 배포

공식 최신 CLI 문서를 다시 확인한 뒤 실행한다.

```bash
npm install --global eas-cli
eas login
eas deploy
```

주의:

- 로그인 토큰이나 인증 코드를 채팅에 붙여 넣지 않는다.
- 첫 연결 화면의 프로젝트/조직이 코인미러 소유 범위인지 확인한다.
- 첫 배포는 production alias가 아닌 preview URL로 실행한다.
- 서버 환경변수는 로컬 `.env` 복사가 아니라 EAS의 서버 전용 환경 설정으로 등록한다.

## 5. Preview 검증

아래의 `PREVIEW_ORIGIN`과 payload는 로컬 변수로만 사용한다. 실제 키나 사용자 데이터를 넣지 않는다.

### 5.1 Route 존재

```bash
curl -i "$PREVIEW_ORIGIN/api/ai-reflection"
```

POST 전용 route이므로 GET의 구체 상태코드보다 **HTML 앱 페이지로 잘못 rewrite되지 않는지**를 확인한다.

### 5.2 Invalid payload 차단

```bash
curl -i -X POST \
  -H 'Content-Type: application/json' \
  --data '{}' \
  "$PREVIEW_ORIGIN/api/ai-reflection"
```

예상: HTTP 400, 민감한 stack·key·provider 응답 원문 없음.

### 5.3 Safe synthetic payload

- 앱의 테스트 fixture가 만드는 **버킷화된 합성 payload만** 사용한다.
- 원본 거래행·종목·금액·파일명·이메일·계정 ID는 사용하지 않는다.
- 응답의 `source`가 `ai`인지 `fallback`인지 확인한다.
- `fallback`이면 내부 enum/code를 UI에 표시하지 않고 기본 코칭을 사용한다.

### 5.4 브라우저 flow

- [ ] landing → 진단 → 합성 업로드 → 결과
- [ ] `AI 행동코칭 받기` 1회 클릭
- [ ] 중복 클릭이 비활성화되는지 확인
- [ ] 응답·fallback·timeout 뒤 로딩이 종료되는지 확인
- [ ] 네트워크 요청 body에 버킷/허용 필드만 있는지 DevTools에서 확인

## 6. Rate-limit 및 비용 보호

현재 코드의 body-size cap과 client timeout은 rate limit을 대체하지 않는다. 서버리스 인스턴스 내부 메모리 카운터는 분산 환경에서 신뢰할 수 없으므로 출시 게이트로 사용하지 않는다.

배포 플랫폼 확정 후 다음 중 플랫폼이 공식 지원하는 방식을 선택한다.

1. edge/WAF 또는 gateway 기반 IP·route 요청 제한
2. AI provider 프로젝트의 월간 비용 한도와 요청 속도 제한
3. route-level abuse 탐지용 비식별 카운터
4. 이상 트래픽 시 AI CTA 비활성화 또는 key 제거로 deterministic fallback 전환

**출시 전 최소 검증:**

- [ ] 동일 client에서 짧은 시간 반복 요청 시 플랫폼 제한 정책이 적용되는지 합성 요청으로 확인
- [ ] 제한 응답에도 key/stack/body가 노출되지 않는지 확인
- [ ] AI key 제거 시 앱 전체가 아니라 AI 코칭만 fallback 되는지 확인
- [ ] EAS request/log 화면에 safe metadata 외 사용자 거래정보가 없는지 확인

## 7. Production 승격 기준

- [ ] preview에서 G1~G5 품질 게이트 통과
- [ ] P0 개인정보/손익 오류 0건
- [ ] 실제 사용자 원본 없이 합성 payload로 route 검증 완료
- [ ] rate limit·비용 상한 확인
- [ ] 커스텀 도메인/개인정보 문구 최종 확인
- [ ] rollback 대상 preview deployment ID 기록(비밀값 아님)

승격 후에도 첫 단계는 5~10명 제한 초대이며, 커뮤니티 공개와 유료 광고는 별도 의사결정이다.

## 8. 장애 대응

| 상황 | 즉시 조치 | 사용자 경험 |
| --- | --- | --- |
| AI provider 장애/비용 초과 | 서버 key 제거 또는 AI CTA 비활성화 | 기본 행동코칭 표시 |
| API route 404/rewrite | production alias 승격 중지, server manifest 재검증 | AI CTA 임시 비활성화 |
| 개인정보 의심 로그 | 신규 요청 중지, 로그 범위 확인, key 회전 검토 | 원인 확인 전 AI 기능 중단 |
| 손익/파싱 P0 | 신규 사용자 초대 중단, 회귀 테스트 작성 | 수정·재검증 전 공개 금지 |
| 과도한 트래픽 | edge 제한 강화, AI key/CTA 중단 | 분석 본체는 local-first로 유지 |
