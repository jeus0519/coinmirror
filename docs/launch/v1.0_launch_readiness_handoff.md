## 1. 이번 완료 범위

### 분석 정확도

- 매수 수수료를 FIFO 진입 원가와 `pnlPct` 분모에 포함했다.
- 부분 청산 시 매수 수수료를 소비 수량에 비례 배분하고 잔여 로트에 남은 수수료를 보존한다.
- 타 종목 체결이 사이에 있어도 같은 종목·방향의 30분 내 연속 체결을 같은 주문으로 병합한다.
- 업비트 CSV의 빈 필수 숫자, 0/음수 가격·수량, 음수 수수료, 존재하지 않는 날짜·시간을 거부한다.
- CSV parser와 업비트 adapter의 순환 의존을 제거했다.

### 지표 설명 정합성

- F3는 시장 급등이 아니라 **90일 이내 같은 종목의 내 직전 거래가 대비 높은 매수**만 측정한다.
- F8은 현재 포트폴리오가 아니라 **분석 기간 전체 매수금액 중 한 종목의 매수금액 비중**을 측정한다.
- 런타임, mock, AI 코칭, 투자거울 타입, 목표, 제품·사업·스코어 문서를 같은 의미로 정렬했다.

### AI 안전 경계

- 요청 최상위·중첩 필드, MBTI, metric ID, score band/bucket을 allowlist로 검증한다.
- 검증 후 입력 객체를 그대로 사용하지 않고 허용된 값만 새 객체로 재구성한다.
- metric `displayName`은 caller 값을 무시하고 서버의 신뢰된 ID 매핑으로 복원한다.
- raw text를 읽은 뒤 UTF-8 byte 기준 2,048-byte 제한을 적용한다.
- malformed JSON, HTTP 오류, 비정상 JSON/schema, timeout, network failure를 구분한다.
- `AbortController` 기반 3,500ms 클라이언트 timeout을 적용한다.
- 서버 `source=fallback` 결과를 AI 생성 문장처럼 표시하지 않고 로컬 기본 행동코칭으로 전환한다.
- 검증된 원격 AI 응답이 성공한 경우에만 해당 분석 fingerprint를 잠근다.
- 실패 시 안내 문구와 30초 쿨다운을 표시하고 최대 3회 재시도한다. 최초 요청을 포함한 총 시도 한도는 4회다.
- 재시도를 모두 소진하면 해당 fingerprint의 추가 요청을 막는다. 처음 보는 새 fingerprint는 별도 상태로 시작하고, 같은 fingerprint로 돌아오면 기존 상태를 유지한다.
- 측정 가능한 지표가 없어 API를 호출하지 않은 경우는 실패 횟수에 포함하지 않는다.
- AI는 행동 회고만 제공하며 종목 추천·가격 예측·매수/매도 지시를 허용하지 않는다.

### PDF 비밀번호 보호

- 브라우저 prompt 대신 화면 내 secure input을 사용한다.
- `secureTextEntry`, `autoComplete="off"`, `textContentType="none"`, 자동 교정·대문자화를 비활성화한다.
- 분석 성공·취소·파일 변경·오류 경로에서 비밀번호 상태를 초기화한다.
- GA4에는 일반화된 성공/실패 코드만 보내며 비밀번호·파일명·거래 원문을 보내지 않는다.


### 정보·이벤트 탭 재구성

- 정보·이벤트 탭을 “시장 배경과 거래소 이벤트” 방향으로 재구성했다.
- 시장 배경은 공포·탐욕 지수, BTC 24시간 가격 변화, 업비트 KRW 시장 관심 분포로 구성한다. BTC 변화는 거래량이 아니라 가격 기준임을 명시한다.
- 업비트 KRW 시장 관심 분포는 BTC·ETH·XRP를 기본 표시하고, 세 자산을 제외한 최근 24시간 거래대금 상위 3개를 추가한다. 각 자산에는 전체 KRW 거래대금 대비 비중을 표시한다.
- `GET /api/market-context`는 15분 서버 캐시와 fallback을 제공하며, 브라우저는 업비트·Alternative.me를 직접 호출하지 않는다.
- `GET /api/exchange-events`는 3시간 서버 캐시와 fallback을 제공한다. 빗썸 목록 파싱 실패와 업비트 최신 목록의 안정적 추출 실패 시 기존 안전 문구와 거래소 링크를 유지한다.
- 거래소 이벤트는 업비트 이벤트 최신 3개와 빗썸 이벤트 최신 3개를 제목·요약·거래소 링크 중심으로 표시한다.
- 이벤트 참여 권유, 과도한 거래 유도, 특정 자산 매수·매도 권유 표현은 금지한다.
- 운영 설계는 서버 캐시 방식이다: 시장 데이터 15분, 이벤트 공지 3시간, 실패 시 stale cache 또는 거래소 링크 fallback.

### Expo server output·Vercel 배포 계약

- `app.json`을 `web.output: "server"`로 정렬했다.
- `src/app/api/ai-reflection+api.ts`, `market-context+api.ts`, `exchange-events+api.ts`에서 기존 검증 handler를 재사용한다.
- Expo server export에서 `/api/ai-reflection`, `/api/market-context`, `/api/exchange-events` API route 생성을 확인했다.
- `api/index.ts`와 `vercel.json`으로 Expo server output을 Vercel Node Function에 연결한다.
- 프로젝트 Node.js runtime은 `24.x`로 고정하고 `@vercel/node` builder 버전은 직접 고정하지 않는다.
- 서버 전용 변수명은 `COINMIRROR_AI_REFLECTION_OPENAI_API_KEY`이며 `EXPO_PUBLIC_*` AI secret 사용을 금지한다.
- 최신 Preview `https://coinmirror-7kz563kdx-data-grida.vercel.app`는 `READY` 상태이며 static route 7개와 API route 3개가 생성됐다.

## 5. 알려진 비차단 리스크

- 실제 업비트 CSV 원본 샘플에 대한 최종 서식 검증은 남아 있다.
- 6자리 고정 반올림은 현재 업비트 KRW 범위에는 차단 근거가 없으나 해외 거래소·초저가 자산 확장 전에 정밀도 정책을 재검토한다.
- 앱 수준 2,048-byte 제한은 edge 단계의 streaming body limit과 rate limit을 대체하지 않는다.
- 실제 fallback 비율, AI 지연, timeout 비율은 제한 트래픽 운영 전에는 알 수 없다.
- `/api/exchange-events`는 최신 Preview 실측에서 `source=fallback`이었다. 외부 HTML 구조 변경에 취약하므로 안정적인 공식 데이터 경로 확보 전에는 거래소 링크 fallback을 유지한다.
- Vercel Preview 환경변수는 현재 0개이고 custom WAF rule도 0개이므로 실제 AI 성공과 429는 아직 검증하지 못했다.
- 다음 기간 재분석률은 시간 경과와 실제 참여자 없이는 검증할 수 없다.
