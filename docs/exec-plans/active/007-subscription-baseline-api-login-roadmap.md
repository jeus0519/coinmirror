# 007 Subscription Baseline, API 연결, 로그인 로드맵

## 목표

구독관리 MVP를 “혜택 설명”에서 “재방문 가치가 있는 기능”으로 확장한다.

1. 이번 분석을 기준선 스냅샷으로 저장한다.
2. 다음 업로드와 직전 기준선을 비교한다.
3. 원본 PDF, PDF 비밀번호, 개별 체결 원문은 저장하지 않는다.
4. 후속으로 거래소/API 데이터 연결 고도화와 로그인 기능 도입을 검토한다.

## 이번 구현 범위

- 분석 결과에서 요약 스냅샷 생성
- 직전 스냅샷 vs 최신 스냅샷 비교
- 비교 대상:
  - 청산 승률
  - 손실 보유기간
  - 수익 보유기간
  - 월평균 주문 수
- 표본 부족 또는 엔진 버전 불일치 시 판단 보류
- 분석 화면에 “이번 분석 저장하기”와 “직전 분석과 비교” 카드 표시
- 이전 스냅샷과 겹치는 체결은 정규화 fingerprint로 자동 제외하고 신규 체결만 다음 스냅샷/비교에 반영
- 기간 밖 매수분이 신규 매도와 연결되는 경우, 중복 매수는 점수/주문 수에 재집계하지 않고 FIFO 원가 연결용 context lot으로만 사용
- 중복 제외 건수, 신규 반영 건수, context lot 보정 건수를 비교 카드에 표시
- 악화된 회고 지표를 목표 후보로 만들고 사용자가 저장할 수 있게 표시
- 다음 분석 비교 시 저장한 목표의 달성/재점검/판단 보류 상태 갱신

## 비범위

- 실제 로그인/회원가입 구현
- 서버 DB 저장
- 실제 결제 PG 연결
- 거래소 API 키 수집/저장
- 다중 스냅샷 시계열 차트
- 이메일 리포트 발송

## 저장 원칙

스냅샷은 명시적 화이트리스트 필드만 저장한다.

저장 가능:

- 분석 ID
- owner id, 현재는 `local-device`
- 분석 생성 시각
- 분석 엔진 버전
- 거래 기간 라벨
- 투자거울 타입 코드/라벨
- F 점수 요약
- 주문 수, 왕복거래 수, 승률, 보유기간, 월평균 주문 수, 미청산 종목 수, 종목 수

저장 금지:

- 원본 PDF 바이너리
- PDF 비밀번호
- 개별 체결 원문
- 계좌/고객 식별자
- 거래소 API secret
- 주문/출금 권한 API 키

## 후속 작업 계획

### 1. API 데이터 연결 고도화 검토

목표는 PDF/CSV 업로드와 거래소/API 연결을 같은 `RawExecution` 파이프라인으로 수렴시키는 것이다.

검토 항목:

- 업비트 Open API에서 조회 전용 키로 체결/주문 내역을 가져올 수 있는 범위
- 사용자 동의/권한 문구
- 주문·출금 권한 키 차단 UX
- API 키 클라이언트 평문 저장 금지
- 서버 저장 시 암호화 저장 또는 세션 한정 사용
- API 연결 실패/권한 부족/기간 제한 안내

MVP 원칙:

- PDF/CSV 경로를 먼저 유지한다.
- API 연결은 구독관리 후속 기능으로 검토한다.
- API 데이터도 기존 엔진 입력인 `RawExecution`으로 변환한다.

### 2. 로그인 기능 구현 검토

로그인은 결제 또는 서버 저장이 필요해질 때 도입한다.

도입 트리거:

- 2회차 업로드 비교가 실제 재방문을 만든다는 신호 확인
- 유료 구독 결제 연동 시작
- 여러 기기에서 기준선을 이어보는 요구 발생

검토 항목:

- 익명 로컬 저장 → 로그인 계정 병합
- `owner_id`를 local-device에서 user id로 전환
- Supabase/Auth.js/Firebase Auth 등 후보 비교
- RLS 기본 활성화
- 사용자 데이터 삭제 기능
- 로그인 없이도 1회 분석 가능한 흐름 유지
