# v1.0 코인미러 분석 신뢰성·AI 안전성·런칭 마케팅 실행계획

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** 무료 공개 전에 분석 정확도와 AI 경계를 출시 가능한 수준으로 보강하고, 업비트 거래내역을 실제로 재분석할 가능성이 높은 초기 고객을 대상으로 2주 런칭 실험을 실행할 수 있게 한다.

**Architecture:** 원본 PDF/CSV의 브라우저 local-first 처리와 공통 `RawExecution → Order → RoundTrip → Metric` 파이프라인은 유지한다. 손익·입력 검증 결함은 순수 TypeScript 모듈에서 TDD로 수정하고, AI 요청은 서버 허용 목록과 검증된 객체 재구성으로 최소화한다. Expo Router API Route와 `web.output: server`를 사용해 클라이언트와 서버 계약을 동일 저장소에 두되, 실제 외부 배포·도메인 연결은 별도 승인 게이트로 남긴다.

**Tech Stack:** Expo SDK 57, Expo Router, React Native Web, TypeScript, `node:test` + `tsx`, Expo Router API Routes, GA4 익명 퍼널 이벤트.

**Sources checked:** Expo 공식 문서의 API Route 규칙(`src/app/*+api.ts`, `web.output: server`)과 웹 output target 표를 2026-09-09 확인했다.

## 4. 런칭 마케팅·타겟팅 실행계획

### 4.1 초기 ICP

**Primary ICP:**
- 업비트에서 최근 1~3개월 동안 반복 매수·매도 기록이 있음
- 자신의 거래 빈도·재진입·손실 보유 습관을 실제 기록으로 확인하고 싶음
- 업비트 원본 PDF를 직접 내려받을 의향이 있음; 검증된 CSV는 보조 입력으로 사용 가능
- 수익 추천보다 개인정보 보호와 자기 회고에 가치를 느낌

**초기 제외:**
- 거래가 거의 없는 장기 보유자
- 종목 추천·가격 예측·수익 보장을 기대하는 사용자
- 빗썸/해외 거래소/증권사 자료만 가진 사용자
- 파일 다운로드 절차를 수행할 의향이 없는 사용자

### 4.2 핵심 메시지

**Hero:** `내가 기억한 투자 습관, 실제 거래 기록과 같을까요?`

**Support:** `업비트 원본 PDF를 브라우저에서 분석해 내 예상과 실제 기록의 차이를 보여드려요. 검증된 CSV도 사용할 수 있으며, 원본 파일은 장기 저장하지 않습니다.`

**CTA:** `내 기록 무료로 비춰보기`

**금지 메시지:** 수익률 개선, 투자 실력 진단, 급등주 포착, 매수·매도 추천, AI 종목 분석.

### 4.3 채널 순서

1. **직접 초대 5~10명:** 업비트 실거래 경험과 파일 제공 의향이 있는 지인/기존 네트워크. 화면 공유 또는 관찰 인터뷰로 마찰을 기록한다.
2. **보유 전문성 채널:** GA4 독자·교육 수강생·데이터 분석 네트워크에는 ‘개인 데이터를 브라우저에서 분석하는 제품 실험’으로 제한 공유한다.
3. **콘텐츠 검증:** `내 예상 vs 기록` 사례를 익명 합성 데이터로 설명하는 글/짧은 영상. 실제 사용자 손익·종목은 공개하지 않는다.
4. **커뮤니티 확장:** 1차 결함 수정 후 커뮤니티 규칙을 확인하고 홍보글이 아니라 무료 도구+검증 요청으로 게시한다. 동일 문구 대량 게시 금지.
5. **유료 광고:** 다음 달 재분석 행동이 확인되기 전 보류한다.

### 4.4 2주 실행 캘린더

**D-7~D-4 — 신뢰성 준비**
- G1~G4 통과
- 업비트 파일 받는 법 안내와 개인정보 안내 QA
- 참여자 5~10명 후보 리스트 작성(개인정보는 앱/GA에 넣지 않음)
- 인터뷰 스크립트와 지원 응답 템플릿 준비

**D-3~D-1 — 관찰형 소프트 런칭**
- 3명에게 직접 링크 전달
- 도움 없이 파일 확보·업로드 가능한지 관찰
- 각 세션의 지원 시간과 막힌 단계 기록
- 치명 결함만 수정하고 기능 요청은 backlog로 분리

**D0~D+3 — 제한 공개**
- 추가 5~7명 초대
- 랜딩→시작→업로드→파싱→결과→AI 코칭→재분석 알림 퍼널 확인
- 파싱 실패 사용자에게 원본 파일 제출을 요구하지 않고 오류 코드·서식 특징만 접수

**D+4~D+7 — 메시지/채널 실험**
- 메시지 A: `내 예상 vs 실제 기록`
- 메시지 B: `원본 파일을 장기 저장하지 않는 월간 투자 회고`
- 유입 수보다 업로드 완료와 결과 이해가 높은 메시지를 선택
- 2회차 업로드 예정일을 사용자가 직접 선택하고, D+30 전후 후속 cohort에서 실제 재방문을 측정

### 4.5 행동 KPI와 초기 판단 기준

아래 숫자는 시장 벤치마크가 아니라 5~10명 소프트 런칭용 운영 기준이다.

| 단계 | 지표 | Green | Yellow | Red |
| --- | --- | ---: | ---: | ---: |
| 입력 | 도움 없이 파일 확보+업로드 완료 | 70% 이상 | 40~69% | 40% 미만 |
| 신뢰 | 업로드 전 개인정보 설명을 정확히 재진술 | 80% 이상 | 50~79% | 50% 미만 |
| 가치 | 본인 말로 새롭게 알게 된 행동 1개 설명 | 60% 이상 | 30~59% | 30% 미만 |
| 안전 | 투자 추천 서비스로 오인 | 0명 | 1명 | 2명 이상 |
| 운영 | 사용자당 수동 지원 중앙값 | 10분 이하 | 11~20분 | 20분 초과 |
| 반복 | 실제 다음 기간 파일로 재분석(D+30 전후) | 후속 cohort 30% 이상 | 10~29% | 10% 미만 |

**단기 Go(D+7):** G1~G5 통과 + 소프트 런칭에서 치명 오류 없음 + 가치 설명 60% 이상. 이 판단은 다음 제한 초대 여부에만 사용한다.

**반복 가치 Go(D+30 전후):** 참여자가 정한 다음 분석 시점의 실제 재분석률을 확인한 뒤 공개 범위와 구독 가설의 다음 단계를 판단한다.

**Iterate:** 업로드 마찰 또는 결과 이해가 Yellow이면 타 거래소/유료 기능 대신 해당 단계만 수정.

**No-Go for paid expansion:** 실제 재분석이 10% 미만이거나 수동 지원 중앙값이 20분을 넘으면 구독 개발을 보류.

### 4.6 익명 이벤트

`landing_view → start_click → diagnosis_complete → upload_attempt → parse_success|parse_failed → result_view → ai_coaching_request_click → reanalysis_reminder_click`

허용 속성은 `screen`, `cta`, `source_format`, `failure_code`, boolean/bucket 값으로 제한한다. 파일명, 비밀번호, 이메일, 종목, 금액, 수량, 손익, 원문은 수집하지 않는다.
