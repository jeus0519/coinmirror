- **검토일**: 2026-08-15
- **검토 범위**: PRD, proposal, Product Specs, PRODUCT_SENSE, 규제·기술 리스크, 프로토타입, 실행 계획
- **현재 기준 지도**: [v1.0 문서 기준 지도](v1.0_documentation_map.md)

## 1. 발견한 주요 충돌과 처리

| 영역 | 충돌 | 처리 결과 |
|---|---|---|
| 제품 핵심 루프 | v1 PRD/초기 Product Spec은 지속적인 일기·감정·목표가 입력을 핵심으로 두었고, 최신 v5.0 스코어 스펙은 반복 입력 없는 자동 분석을 확정 | v2.0 PRD에서 설문 1회 + 거래 데이터 자동 분석을 핵심으로 통일. 수동 기록은 선택 기능으로 격하 |
| 온보딩 질문 | Expo/HTML은 7문항, 최신 v5.0 스펙은 해석 기준 4 + 자기 예상 4의 8문항 | 문서 기준은 v5.0 8문항으로 확정. 구현 차이는 Tech Debt에 등록 |
| 설문과 점수 | v5.0 초안 일부 공식이 투자 스타일·예상 시간대에 따라 페널티와 종합 가중치를 바꿔 “설문은 점수에 개입하지 않는다” 원칙과 충돌 | A1/A2/A3/B2는 해석·순서·예상 비교에만 사용하도록 공식 수정. F8의 사용자 선언 한도만 정의상 예외로 유지 |
| 스코어 수 | 데모 M1~M6, v1 스코어 문서는 기본 10 + 확장 20 + 파생 20, v5.0은 Free 9+1 및 구독 7 | 현재 제품 기준은 F1~F10 + P1~P7. v1 50종 문서는 history로 이동 |
| 점수 방향 | 데모는 위험도형이 높을수록 빈발, 최신 스펙은 모든 점수가 높을수록 양호 | 문서는 높을수록 양호로 통일. 데모 교체 작업을 Tech Debt에 등록 |
| 목표 관리 | 데모/구 PRD는 숫자 입력과 자유 워크시트, v5.0은 프리셋 원칙을 탭으로 선택 | P7 프리셋 원칙을 현재 기준으로 확정. 기존 UI는 교체 필요 |
| 요금제 | v6 proposal은 LITE·PDF 일회성·PRO·챌린지·평생권 등 다단계, 최신 사용자 결정은 Free + 구독관리 | v7.0 proposal에서 2단계로 통일. v6는 history로 이동 |
| PDF | 구 PRD는 PDF 업로드를 MVP 핵심으로, 최신 스코어 스펙은 CSV/API 자동 산출 중심 | CSV를 MVP 기본값으로 확정. PDF는 성공률/운영비 PoC 이후로 이동 |
| API/실시간 | 일부 과거 아이디어는 실시간 알림·API 감시를 포함, 현재 방향은 Batch-First | Read-Only API는 후속 핵심, 실시간 매매 개입·웹소켓 감시는 비목표로 통일 |
| IA | 구 PRD의 4개 앱 탭과 현재 6단계 스테퍼가 충돌하는 것처럼 기술됨 | 6단계는 초기 온보딩/데모, 4개 영역은 장기 앱 IA로 역할을 분리 |
| 실행 계획 | `active/001`이 4단계 목업 완료 상태인데 계속 진행 중으로 남음 | `exec-plans/completed/`로 이동 |
