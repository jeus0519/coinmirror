# RELIABILITY

MVP 단계의 최소 원칙. 사용자가 늘어나면 이 문서를 확장한다.

## 오프라인/네트워크 오류

- Supabase 요청 실패 시 사용자에게 "저장 실패, 다시 시도" 등 명확한 피드백을 준다. 조용히 실패시키지 않는다.
- 회고 기록처럼 사용자가 방금 입력한 데이터는 네트워크 실패로 유실되면 안 된다 — 실패 시 로컬 상태(Zustand)에 남겨두고 재시도 가능하게 한다.

## 크래시/에러 리포팅

- 아직 미도입. 알파 테스터가 생기면 Sentry 등 도입 검토 (`docs/exec-plans/`에 계획 작성 후 진행).

## 기준

- 앱 시작(Splash → 첫 화면)이 체감상 즉시여야 한다.
