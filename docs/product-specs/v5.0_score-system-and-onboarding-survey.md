### 0.2 방향 통일 (개발·UX 공통 규칙)

- 모든 스코어는 **0~100, 높을수록 절제/규율 양호**로 통일한다. (데모 HTML의 "위험도형은 높을수록 빈발" 방식은 혼선을 유발하므로 폐기)
- UI 밴드: `80~100 안정` / `55~79 관찰` / `0~54 주의` — **⚠️ 미검증 — 캘리브레이션 필요**. 밴드 문구는 평가가 아니라 빈도 서술로 쓴다.
- 표본 미달 시 점수를 만들지 않고 `측정 중` + "무엇이 몇 건 더 필요한지" 표시 (PRD 6.5 원칙 승계).
- 설문 답변은 **실제 거래 기반 점수를 가감하지 않는다.** 해석 문구, 카드 우선순위, 예상 vs 실제 비교에만 쓴다. 유일한 예외는 사용자가 직접 정한 한도와의 대조 자체가 정의인 F8이며, 한도 미설정 시 점수 대신 실측 집중도만 표시한다.

## 1. 공통 계산 기반 (스코어 엔진 전처리)

모든 스코어는 아래 전처리 산출물 위에서 계산한다. `lib/score-engine/` 에 구현.

### 1.1 주문 병합 (Order)

```
같은 (symbol, side)의 체결이 30분 이내에 연속되면 1건의 Order로 병합
- price = 체결금액 가중평균, quantity = 합계, executedAt = 첫 체결 시각
- 이유: 분할 체결 1회 주문이 체결 건수를 부풀리는 것 방지 (데모와 동일)
```

### 1.2 라운드트립 재구성 (RoundTrip)

```
종목별 FIFO 매칭으로 매수 로트 → 매도 체결을 짝지어 RoundTrip 생성
RoundTrip = {
  symbol, entryOrders[], exitOrder,
  avgEntryPrice, exitPrice,
  amount(원화 취득원가), pnl(수수료 차감), pnlPct,
  holdingHours(첫 진입~청산), closedAt
}
- 부분 매도는 매도 1건 = RoundTrip 1건 (남은 로트는 미청산 유지)
- pnl > 0 → ProfitExit, pnl < 0 → LossExit, |pnlPct| < 0.1% → BreakevenExit
```

### 1.3 파생 시계열

`src/lib/score-engine/derived-series.ts`에 구현한다. 입력은 CSV가 아니라 전처리된 `Order[]`와 `RoundTrip[]`만 받는다.

```
- hourlyAmount[0..23]: KST 기준 시간대별 거래대금
- weekdayOrderCount[0..6]: 월~일 Order 수
- perSymbolBuyShare: 종목별 매수금액 비중 내림차순
- winRate: ProfitExit / 전체 Exit. Exit 0건이면 null
- medianHoldingHours: 이익·손실 RoundTrip별 중앙 보유시간. 한쪽 표본이 없으면 null
- monthlyOrderCount: 분석 기간을 월 단위로 환산한 평균 Order 수
- totalOrderAmount, realizedPnl, openPositionCount: 분석 화면 요약 숫자
```

위 값은 「예상 vs 실제」, 시간대/요일 차트, 종목별 비중, 거래 개요 카드의 공통 원천이다. 샘플 경로와 CSV 경로 모두 같은 파이프라인을 통과한다.

### 1.4 외부 데이터 (선택적, 배치 시점 1회 조회)

| 데이터              | 용도                              | 없을 때                                                       |
| ------------------- | --------------------------------- | ------------------------------------------------------------- |
| 배치 시점 현재가    | F1의 미청산 손실 방치 항목        | 해당 페널티 항 제외 후 나머지 항만으로 산출 (가중치 재정규화) |
| 일봉 OHLCV          | F3 시장준거 룰, F9 정밀화         | 자기준거 룰만 사용                                            |
| BTC/ETH 주간 수익률 | P3 하락장 적응력, P6 운·규율 분해 | 해당 구독 스코어 `준비 중` 처리                               |

원칙: **외부 데이터가 전혀 없어도 Free 스코어 전부가 계산되어야 한다.** 외부 데이터는 정밀화 용도로만.

## 3. Free 스코어 9종 + 종합 1종

모든 스코어: `score = 100 - Σ페널티`, 각 페널티는 캡 존재, 최종 `clamp(0, 100)`. `P = min(캡, 계산값)` 표기. 정렬은 고객 체감 가치순. **아래 모든 계수·캡·최소 표본·가중치는 ⚠️ 미검증 — 캘리브레이션 필요 초안이다.**

### F1. 손절 습관 점수

- **한 줄 정의**: 손실 종목을 얼마나 미루지 않고 정리했는가.
- **입력**: RoundTrip 전체, (선택) A3 자기 기준 L, (선택) 배치 시점 현재가.
- **산출**:
  ```
  lossRTs = LossExit RT, profitRTs = ProfitExit RT
  h = median(holdingHours(lossRTs)) / median(holdingHours(profitRTs))
  P1(보유 비대칭, 캡40 ⚠️ 미검증) = (h - 1) * 25          // 임의 초안값 · 캘리브레이션 필요
  tail = count(pnlPct ≤ -20%) / count(lossRTs)
  P2(깊은 손실 비중, 캡30 ⚠️ 미검증) = tail * 60          // 임의 초안값 · 캘리브레이션 필요
  현재가 있을 때:
    drag = Σcost(미청산 & 평가손실 ≤ -20% & 보유 60일↑) / Σcost(미청산)
    P3(방치 비중, 캡30 ⚠️ 미검증) = drag * 60          // 임의 초안값 · 캘리브레이션 필요
  현재가 없으면 P3 제외, P1·P2 캡을 각각 50·40으로 재정규화
  ```
- **최소 표본**: LossExit 5건 + ProfitExit 3건 — **⚠️ 미검증 — 캘리브레이션 필요**. 미달 시 `측정 중 · 손실 청산 기록 N건 더 필요`.
- **설문 연결**: A3(실측 손실 중앙값과 나란히 표시), A2-②(우선 노출).
- **고객 노출 의미(한 문장)**: "잃고 있는 코인을 벌고 있는 코인보다 얼마나 오래 붙잡고 있었는지 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 정리할지 말지는 언제나 본인의 판단이에요. 다만 미리 정해둔 점검 기준(-10%)을 지나친 포지션을 일주일에 한 번 들여다보는 것만으로도, 미루는 습관이 줄어드는지 다음 분석에서 확인할 수 있어요."
- **행동경제학 이론**: 처분효과(Shefrin & Statman), 손실회피(Kahneman & Tversky).
- **문구 예시**: "손실 포지션 평균 보유시간이 이익 포지션의 3.1배였습니다. 정해두신 점검 기준은 -10%였고, 실제 손실 청산 중앙값은 -18%였습니다."

### F2. 익절 습관 점수

- **한 줄 정의**: 이익을 계획 없이 서둘러 끊는 비대칭이 얼마나 강한가.
- **산출**:
  ```
  A = median(|pnlPct|(lossRTs)) / median(pnlPct(profitRTs))   // 손익폭 비대칭
  P1(손익폭 비대칭, 캡45 ⚠️ 미검증) = (A - 1) * 22                       // 임의 초안값 · 캘리브레이션 필요
  t = median(holdingHours(profitRTs)) / median(holdingHours(lossRTs))
  P2(조기 정리, 캡30 ⚠️ 미검증) = max(0, 1 - t) * 30
  P3(초단기 익절 집중, 캡25 ⚠️ 미검증) = count(profitRT & pnlPct < +2% & holdingHours < 6) / count(profitRTs) * 50
  ```
- **최소 표본**: ProfitExit 5건 + LossExit 3건 — **⚠️ 미검증 — 캘리브레이션 필요**.
- **설문 연결**: B3(예상 비대칭 — 공개 카드·P5용), A1(해석 문구만 조정).
- **고객 노출 의미(한 문장)**: "이익은 서둘러 팔고 손실은 오래 버티는, 거꾸로 된 습관이 있는지 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 이익 난 코인을 팔고 싶어질 때 '지금 파는 이유'를 한 번만 스스로에게 물어보세요. 다음 분석에서 +2% 미만 초단기 익절 비중이 줄었는지 보면, 그 질문이 효과가 있었는지 알 수 있어요."
- **행동경제학 이론**: 처분효과의 이익 측면, 확실성 효과(작지만 확실한 이익 선호).

### F3. 추격매수 점수

- **한 줄 정의**: 이미 오른 가격을 따라 들어간 매수가 얼마나 되는가.
- **산출**:
  ```
  chase(B) = 다음 중 하나면 참:
    (a) 자기준거: B.price ≥ 1.07 × lastTradePrice(symbol, 직전 90일 내)   // 필수 룰
    (b) 시장준거: OHLCV 있을 때, 매수 전일 종가 대비 당일 매수가 ≥ +15%    // 선택 룰
  chaseShare = Σamount(chase 매수) / Σamount(전체 매수)
  P1(캡50 ⚠️ 미검증) = chaseShare * 90             // 합성 픽스처 기준 1차 보정값 · 실제 데이터 캘리브레이션 필요
  P2(반복 추격, 캡15 ⚠️ 미검증) = 동일 종목 추격 2회 이상 발생 종목 수 / 거래 종목 수 * 20
  ```
- **최소 표본**: 매수 Order 10건 — **⚠️ 미검증 — 캘리브레이션 필요**.
- **설문 연결**: A2-①(우선 노출).
- **고객 노출 의미(한 문장)**: "이미 오른 가격을 뒤따라 들어간 매수가 전체 매수에서 얼마나 되는지 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 급등을 본 순간 매수 버튼 대신 30분 타이머를 먼저 눌러 보세요. 30분 뒤의 판단은 온전히 본인의 몫이지만, 이 점수는 '기다린 뒤의 매수'가 늘었는지를 다음 분석에서 보여줄 거예요."
- **행동경제학 이론**: FOMO, 허딩(군집 행동), 주의 기반 매수(Barber & Odean).
- **주의**: T+1 회고 전용. 실시간 과열 알림 금지.

### F4. 물타기 점수

- **한 줄 정의**: 하락 구간 추가매수가 계획된 분할인지 반사적 대응인지.
- **산출**:
  ```
  dca(B) = 보유 중 종목 & B.price ≤ 0.90 × avgEntry(현재 평단)
  dcaShare = Σamount(dca) / Σamount(전체 매수)
  P1(캡50 ⚠️ 미검증) = dcaShare * 150
  esc = median(dca 금액 / 같은 종목 직전 매수 금액)
  P2(증액, 캡25 ⚠️ 미검증) = max(0, esc - 1) * 25          // 임의 초안값 · 캘리브레이션 필요
  quick = count(dca & 직전 같은 종목 매수 후 24h 이내) / count(dca)
  P3(반사 간격, 캡25 ⚠️ 미검증) = quick * 50
  ```
- **이벤트 0건이면**: 100점 + "기간 내 물타기성 매수가 기록되지 않았습니다".
- **설문 연결**: A2-③(우선 노출), A3(문구에 자기 기준 병기).
- **고객 노출 의미(한 문장)**: "떨어질 때 추가로 산 매수가 계획된 분할이었는지, 반사적인 대응이었는지 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 추가매수 자체는 전략일 수 있어요. 다만 '몇 번에 나눠, 얼마씩'을 미리 정해 두면, 이 점수가 계획된 분할과 반사적 물타기를 구분해 줄 수 있어요."
- **행동경제학 이론**: 매몰비용 오류, 앵커링(평단 앵커), 본전 심리.
- **주의**: 물타기 자체를 악으로 표현 금지 — 증액·간격 패턴만 서술.

### F5. 복구매수 점수 (손실 후 재진입)

- **한 줄 정의**: 손실을 확정한 직후, 만회하려는 매수가 얼마나 빨리·크게 나오는가.
- **산출**:
  ```
  reentry(B) = 아무 종목이든 LossExit 후 2시간 이내의 매수
  r = count(재진입 발생 LossExit) / count(LossExit)
  P1(캡50 ⚠️ 미검증) = r * 100
  m = median(reentry 금액 / median(최근 20건 매수 금액))
  P2(베팅 확대, 캡30 ⚠️ 미검증) = max(0, m - 1) * 30
  burst = count(LossExit 당일 Order 수 ≥ 3 × 일평균) / count(LossExit 발생일)
  P3(폭주, 캡20 ⚠️ 미검증) = burst * 40
  ```
- **최소 표본**: LossExit 5건 — **⚠️ 미검증 — 캘리브레이션 필요**.
- **설문 연결**: A2 관련 없음(전원 노출 후보), B2(야간 재진입이면 문구에 시간대 병기).
- **고객 노출 의미(한 문장)**: "손실을 확정한 직후, 만회하려고 서둘러 다시 들어가는 패턴이 있는지 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 손실을 확정한 날은 '2시간 쉬기'를 나만의 원칙으로 정해 보세요. 원칙 지키기 카드에서 탭 한 번으로 설정하면, 다음 분석 때 지켜졌는지 자동으로 확인해 드려요."
- **행동경제학 이론**: 리벤지 트레이딩, 전망이론의 손실영역 위험추구.
- **주의**: 손실 상태에서 푸시 알림 금지, 앱 내 회고 전용.

### F6. 과매매 점수

- **한 줄 정의**: 거래 횟수와 수수료가 최근 내 거래 기준에서 과열된 정도.
- **산출**:
  ```
  d = 일평균 Order 수(활동일 기준)
  base = 직전 4주 활동일 기준 일평균 Order 수
  P1(자기 기준 급증, 캡30 ⚠️ 미검증) = max(0, d - base) / max(base, 1) * 30
  sameDay = count(당일 같은 종목 매수+매도 왕복) / count(활동일)
  P2(당일 왕복, 캡30 ⚠️ 미검증) = sameDay * 110
  feeDrag = totalFee / max(|realizedPnl|, totalFee)
  P3(수수료 마찰, 캡40 ⚠️ 미검증) = feeDrag * 80
  ```
- **첫 분석 처리**: 직전 4주 기준선이 없을 때는 `base`를 같은 구간 중앙값으로 자기참조하지 않는다. P1을 제외하고 P2/P3만 사용하며, 캡을 P2 45 · P3 55로 재정규화한다. 수수료 컬럼이 없으면 P3를 제외하고 해당 캡을 P2에 합산해 조용한 오산을 피한다. 이 처리는 F1에서 현재가 부재 시 항 제외 후 캡 재정규화하는 선례와 동일하다.
- **최소 표본**: Order 20건 — **⚠️ 미검증 — 캘리브레이션 필요**.
- **설문 연결**: A1(해석 문구), A2-④(우선 노출), B1(예상 횟수 — 공개 카드).
- **고객 노출 의미(한 문장)**: "거래 횟수와 수수료가 내 투자 스타일에 비해 과했는지 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 이번 달 수수료 합계를 한 번 확인해 보세요. 일주일에 하루만 '매매 없는 날'을 만들어도, 다음 분석에서 이 점수의 변화로 확인할 수 있어요."
- **행동경제학 이론**: 과잉거래와 과신(Barber & Odean, "Trading is hazardous to your wealth"), 비용 무시. 수수료 절대액은 카드에 원화로 표시 — CSV 분석의 최대 아하모먼트.
- **주의**: 단타 스타일에 절대 횟수 감점 금지(styleCap이 담당). "거래를 줄이면 수익이 는다" 금지.

### F7. 새벽거래 점수

- **한 줄 정의**: 00~06시 거래가 전체에서 차지하는 비중.
- **산출**:
  ```
  nightShare = Σamount(00:00~06:00 KST Order) / Σamount(전체)
  base = 직전 4주 자기 nightShare (첫 분석은 0.10 고정 기준)
  P1(캡60 ⚠️ 미검증) = nightShare * 150
  P2(자기 패턴 이탈, 캡40 ⚠️ 미검증) = max(0, nightShare - base) * 200
  ```
- **최소 표본**: Order 15건 — **⚠️ 미검증 — 캘리브레이션 필요**.
- **설문 연결**: B2, A2-⑤(우선 노출).
- **고객 노출 의미(한 문장)**: "판단력이 흐려지기 쉬운 새벽 시간대의 거래가 얼마나 되는지 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 자정 이후에는 거래 앱을 열지 않는 규칙을 시도해 보세요. 시간은 아홉 가지 습관 중 가장 바꾸기 쉬운 것이라, 효과가 다음 분석에 가장 빨리 나타나요."
- **행동경제학 이론**: 자기통제 자원 고갈(ego depletion), 수면 부족과 위험선호 증가. 개선 액션이 가장 구체적인 스코어 → P7 프리셋 원칙과 직결.

### F8. 몰빵 점수

- **한 줄 정의**: 최근 매수 자금이 한 종목에 몰린 정도를 **내가 정한 한도**와 비교.
- **산출**:
  ```
  topShare = max_symbol( Σamount(해당 종목 매수, 최근 4주) ) / Σamount(전체 매수, 최근 4주)
  C = A4 선언 한도 (0.10 / 0.30 / 0.50)
  A4 미선언(⑤) 또는 무제한(④) 시: 점수 미산출. 카드에는 topShare 실측만 표시
    + "한도를 정하면 이 점수가 켜져요" (탭 1회 재선언 가능)
  P1(캡80 ⚠️ 미검증) = max(0, topShare - C) * 200
  P2(동시 노출, 캡20 ⚠️ 미검증) = count(동시 보유 종목 1개인 활동일) / 활동일 * 40
  ```
- **최소 표본**: 매수 10건 & 거래 종목 2개 이상 — **⚠️ 미검증 — 캘리브레이션 필요**. 1종목 전용 유저는 `측정 중` 아닌 실측 표시.
- **설문 연결**: A4(유일한 기준 — 앱이 한도 기본값 제시 금지), A2-⑥(우선 노출).
- **고객 노출 의미(한 문장)**: "최근 매수 자금이 한 종목에 얼마나 몰렸는지, 내가 정한 한도와 비교해 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — '분산하라'는 뜻이 아니에요. 내가 정한 한도를 넘긴 날이 언제였는지 확인하고, 그 한도를 계속 유지할지 새로 정할지만 선택해 보세요. 기준은 언제나 본인이 정해요."
- **행동경제학 이론**: 과신, 좁은 프레이밍(narrow framing), 친숙성 편향.
- **주의**: "거래 기준" 명시(계좌 전체 비중 아님 — 예수금 데이터 없음).

### F9. 본전 탈출 점수

- **한 줄 정의**: 물렸다가 본전 근처에 오면 바로 던지는 습관이 있는가.
- **산출**:
  ```
  be(RT) = 0% ≤ pnlPct ≤ +1.5%
  베이스 룰: beShare = count(be) / count(전체 Exit)
    P1(캡60 ⚠️ 미검증) = max(0, beShare - 0.15) * 300     // 임의 초안값 · 캘리브레이션 필요
  OHLCV 있을 때 정밀화: be 중 RT 기간 내 최저가가 평단 대비 -5% 이하였던 건만 인정
    (한 번도 물리지 않은 본전 청산은 제외)
  P2(본전 집중 클러스터, 캡40 ⚠️ 미검증) = count(be & holdingHours > 72) / count(be) * 60
    // 오래 버티다 본전에 턴 것 = 본전 심리 신호가 더 강함
  ```
- **최소 표본**: Exit 10건 — **⚠️ 미검증 — 캘리브레이션 필요**.
- **설문 연결**: 없음.
- **고객 노출 의미(한 문장)**: "물렸다가 본전 근처가 되면 서둘러 파는 습관이 있는지 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 오래 버틴 끝에 +1%로 정리한 거래가 있다면, 그때 '버틴 이유'와 '판 이유'가 같은 이유였는지 돌아보세요. 이유가 달랐다면 가격이 아니라 본전이라는 숫자가 결정을 대신한 것일 수 있어요."
- **행동경제학 이론**: 본전 심리(breakeven effect), 앵커링. 일반 서비스에 없는 차별 지표 — "버틴 보상이 +0.8%였던 거래 5건"을 직면.

### F10. 투자 체력 종합점수 (홈 대표 — PRD S10)

- **산출**:
  ```
  기본 가중치: F1 15, F2 12, F3 15, F4 10, F5 12, F6 12, F7 8, F8 8, F9 8  (합 100)  // ⚠️ 미검증 — 캘리브레이션 필요
  A2 선택 고민은 카드 순서에만 반영하고 종합점수 가중치는 변경하지 않음
  측정 중/미산출 스코어는 가중치에서 제외 후 재정규화 (0점 처리 금지)
  신뢰도 = f(측정된 스코어 수, 총 표본): 7개↑ & Order 60↑ '높음' / 5개↑ '중간' / 그 외 '낮음'
  홈 표시: 절대점수보다 4주 변화량 우선 ("지난 분석 대비 +6점")
  ```
- **고객 노출 의미(한 문장)**: "아홉 가지 습관 점수를 하나로 모은, 지금 내 투자 습관의 체력이에요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 점수 자체보다 지난 분석 대비 변화를 보세요. 한 번에 전부 고치려 하기보다, 가장 낮은 습관 하나만 골라 4주 동안 지켜보는 편이 오래가요."
- **주의**: 수익률과 같은 카드/뷰포트에 배치 금지 (인과 오해 방지).

## 4. 구독 스코어 7종 (전부 자동 산출 — 추가 입력 없음)

구독 가치 = 무료로 보여준 신호를 **추세화·비교·관리**. P7만 "탭 1회 선택"이 필요하고 나머지는 완전 자동.

### P1. 습관 변화 그래프

주간 배치마다 F1~F9 재계산 → 12주 시계열. `개선률 = (최근 4주 평균 - 이전 4주 평균)`을 스코어별 표시, 종합점수 변화의 스코어별 기여도 분해(워터폴)를 함께 제공. 단위는 반드시 "점"(수익 오해 방지).

- **고객 노출 의미(한 문장)**: "12주 동안 어떤 습관이 좋아졌고, 어떤 습관이 되돌아왔는지 한눈에 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 매주 아홉 개를 전부 볼 필요는 없어요. 가장 크게 움직인 스코어 하나만 골라, 그 주에 어떤 거래가 있었는지 돌아보세요."

### P2. 회복탄력성 지수

```
이탈 주 = 어떤 F스코어가 자기 8주 이동평균 대비 -15점 이하로 떨어진 주
복귀 = 이동평균 -5점 이내로 회복
P1(재발, 캡50) = 재발 횟수 / 관측 주수 * 150
P2(복귀 지연, 캡50) = max(0, 평균 복귀 주수 - 1) * 15
score = 100 - P1 - P2   // "무너져도 2주 만에 돌아왔다"는 서사로 표시
```

최소 표본: 12주 데이터. "실패/재발" 낙인 문구 금지.

- **고객 노출 의미(한 문장)**: "습관이 무너졌을 때, 얼마나 빨리 제자리로 돌아오는지 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 무너진 주가 있다는 건 실패가 아니라 데이터예요. '한 번도 안 무너지기'보다 '돌아오는 데 걸리는 기간 줄이기'를 목표로 삼아보세요."

### P3. 하락장 적응력

```
주간 BTC 수익률로 국면 라벨: 상승(≥+5%) / 하락(≤-5%) / 횡보(그 외)  — T+1 확정치만
국면별 F1~F9 평균의 최대 편차 D
score = 100 - min(100, D * 2)
표시: "하락 주간의 복구매수 점수는 41점, 상승 주간은 78점이었습니다"
```

현재 국면 판단 표시 금지. BTC 데이터 없으면 `준비 중`.

- **고객 노출 의미(한 문장)**: "시장이 오를 때와 내릴 때, 내 습관이 얼마나 달라지는지 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 하락 주간에 유독 무너지는 습관이 하나 있다면, 그 습관과 연결된 원칙을 미리 하나 정해 두세요. 시장은 고를 수 없지만 그때의 내 행동 기준은 미리 고를 수 있어요."

### P4. 또래 거울

주간 익명 집계(옵트인 요약 데이터, n ≥ 100일 때만)에서 F1/F3/F6의 백분위. **수익률 비교 절대 금지, 행동 지표만. 하향 비교 문구 금지** — 상위 규범 제시형("새벽거래 점수 상위 25% 사용자의 야간 비중은 4% 이하")만 허용.

- **고객 노출 의미(한 문장)**: "같은 습관을 관리하고 있는 다른 사용자들 사이에서, 내 행동이 어디쯤인지 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 순위 경쟁이 아니에요. 수익이 아니라 '행동'만 비교하니, 상위 사용자들의 야간 비중이나 왕복 횟수 같은 숫자를 내 다음 기준을 정할 때 참고로만 삼아보세요."

### P5. 자기인식 갭

```
블록 B 각 응답을 구간 중앙값으로 환산, 실측과 비교:
gap_i = min(1, |declared_mid_i - actual_i| / bucket_width_i)
score = 100 - mean(gap_i) * 100
12주 추적: 분기마다 블록 B만 재질문(4탭, 30초) → 갭 추세 그래프
```

"거짓말/착각" 표현 금지. 온보딩 공개 카드의 구독 확장판.

- **고객 노출 의미(한 문장)**: "'내가 생각하는 나'와 '기록에 남은 나' 사이의 거리를 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 거리가 가장 큰 항목 하나를 이번 분기의 관찰 대상으로 정해 보세요. 다음 재질문 때 그 거리가 줄었다면, 내 감각이 기록을 따라잡고 있다는 뜻이에요."

### P6. 운·규율 분해 (분기 리포트)

```
RT별 시장기여 = 보유기간 동일 구간의 BTC 수익률 × 취득원가
실현손익 = Σ시장기여 + 행동잔차 + (-수수료) 로 분해 표시
비교군: '신호 거래'(F3 추격 or F5 재진입에 걸린 RT) vs '무신호 거래'
표시: 두 군의 pnlPct 표준편차 비교 ("신호 거래군의 결과 편차가 2.8배 컸습니다")
```

"규율 지키면 더 번다" 금지 — 평균이 아니라 분산(안정성)만 말한다.

- **고객 노출 의미(한 문장)**: "이번 분기 손익이 시장 흐름 덕분이었는지, 내 행동의 결과였는지 나눠서 보여줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 금액보다 들쭉날쭉함(편차)을 보세요. 추격이나 복구매수 신호가 있던 거래일수록 결과가 크게 출렁였다면, 다음 분기에는 그 신호 하나를 줄이는 원칙부터 시도해 볼 만해요."

### P7. 원칙 지키기 (프리셋 선택형 — 유일한 상호작용)

숫자 입력 없음. 원칙 카드에서 탭 1회로 선택, 강도는 3단계 프리셋:

| 프리셋 원칙         | 판정 지표              | 강도(느슨/보통/엄격) |
| ------------------- | ---------------------- | -------------------- |
| 새벽 매수 줄이기    | F7 nightShare          | 20% / 10% / 5% 이하  |
| 당일 왕복 줄이기    | F6 sameDay 주간 횟수   | 4 / 2 / 0회 이하     |
| 추격매수 줄이기     | F3 chase 월간 건수     | 6 / 3 / 1건 이하     |
| 손실 직후 쉬기      | F5 2h 재진입 월간 건수 | 4 / 2 / 0건 이하     |
| 한 종목 한도 지키기 | F8 topShare            | A4 선언값 그대로     |

동시 활성 최대 2개. 다음 데이터 동기화 때 자동 판정 → 주간 준수 표시 + 연속 준수 스트릭. 2주기 연속 미달 시 한 단계 느슨한 프리셋 제안(사용자 승인 필요). "실패" 표현 금지.

- **고객 노출 의미(한 문장)**: "내가 고른 원칙을 실제로 지켰는지, 다음 거래 기록에서 자동으로 확인해 줘요."
- **관리 제안 코멘트**: "이렇게 관리해 보면 좋아요 — 원칙은 한 번에 두 개까지만, 첫 4주는 '느슨한' 강도로 시작해 보세요. 지켜지는 경험이 먼저 쌓여야 다음 단계로 조이는 것도 오래가요."

### 5.4 캘리브레이션 절차

Phase 1의 명시적 산출물은 실제 사용자 데이터가 아니라 합성 픽스처 기반 1차 캘리브레이션이다.

1. `추격형 전형`, `손절 못 하는 전형`, `정상 거래` 합성 픽스처를 만든다.
2. 각 픽스처가 의도한 F1/F3/F6/F8 밴드와 투자거울 타입으로 판정되는지 테스트한다.
3. 의도 밴드에 떨어지지 않으면 `src/lib/score-engine/score-constants.ts`의 상수를 조정한다.
4. 조정 결과는 이 문서와 실행 계획에 남긴다.
5. 실제 사용자 표본이 생기기 전까지 모든 상수는 `⚠️ 미검증 — 캘리브레이션 필요` 상태로 유지한다.

## 6. 컴플라이언스 (전 스코어 공통 — PRD §10 승계)

- 모든 문구 과거형·행동 주어·T+1 회고. 금지: 추천/예측/적정가/수익 개선 약속/실시간 행동 권유.
- 설문·프리셋의 기준값은 항상 사용자 선언 — 앱이 한도·손절폭·원칙 기본값을 "권장"하는 표현 금지 (프리셋은 나열만, 선택은 사용자).
- 점수와 수익률 동일 카드 배치 금지. P4 수익률 비교 금지. P6은 분산만.
- 손실 확정·드로다운 상태에서 푸시 발송 금지 (F5 관련).
- **관리 제안 코멘트 작성 규칙**: 제안 대상은 언제나 '습관·환경·기록 확인'(타이머, 무매매일, 앱 사용 규칙, 회고)이며 매매 행위 자체(사라/팔라/버텨라/정리하라)를 제안하지 않는다. 판단 주체가 사용자임을 문장 안에 명시한다("본인의 판단", "기준은 본인이 정해요"). 효과 표현은 수익이 아니라 "다음 분석에서 변화를 확인"으로 제한한다.
