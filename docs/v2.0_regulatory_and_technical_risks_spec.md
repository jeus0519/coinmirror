# v2.0 코인미러 규제 및 기술 리스크 명세

- **상태**: 현재 기준
- **기준일**: 2026-08-15
- **제품 기준**: [v2.0 PRD](v2.0_coinmirror_product_prd.md)
- **스코어 기준**: [v5.0 스코어 시스템](product-specs/v5.0_score-system-and-onboarding-survey.md)

## 1. 변하지 않는 경계

1. 과거 거래에 대한 회고만 제공한다.
2. 미래 가격, 매수·매도 시점, 적정 비중을 제시하지 않는다.
3. 자산을 보관하거나 주문·출금을 실행하지 않는다.
4. 거래소 API를 지원하더라도 Read-Only 권한만 사용한다.
5. 원본 거래 데이터는 Local-First로 처리한다.
6. 스코어와 수익률 사이의 인과를 주장하지 않는다.
7. 리포트 채널은 이메일을 기본으로 하되, 리포트 메일과 광고성 정보는 동의·해지를 분리한다.
8. 창업자 본인의 겸업·이해충돌 확인 전에는 출시하지 않는다.

## 2. 규제·카피 리스크

| 리스크                | 통제                                                                          |
| --------------------- | ----------------------------------------------------------------------------- |
| 투자 추천으로 오인    | 모든 문장을 과거형·행동 주어로 제한하고 금지 표현 필터 적용                   |
| 수익 개선 약속        | 성과 대신 기록 빈도, 패턴, 변화만 표현                                        |
| 사용자 성향 평가 오인 | 설문은 투자 적합성/위험등급 평가가 아니라 해석 기준과 자기 예상 수집임을 고지 |
| 현재 시장 판단 오인   | T+1 이후 확정된 과거 데이터만 분석. 현재 국면 매매 지시 금지                  |
| 또래 비교의 경쟁화    | 수익률 비교 금지, 행동 집계만 사용, n≥100 및 옵트인 적용                      |

### 필수 고지

> 본 서비스는 과거 거래 데이터를 기반으로 투자 습관을 요약하는 회고 도구입니다. 특정 가상자산의 매수·매도 추천, 가격 예측, 투자 자문, 원금 또는 수익 보장을 제공하지 않습니다.

## 3. 개인정보·보안

- CSV 원본과 거래 원장은 기기 로컬 또는 분석 세션 안에서 우선 처리한다.
- 서버 전송은 명시적 동의를 받은 최소 집계 데이터부터 시작한다. 이메일 리포트 발송에 필요한 점수·타입·밴드·분석 기준일만 보관하고, 원본 거래내역·종목별 원장·체결 단위 데이터는 서버에 올리지 않는다.
- 삭제와 내보내기 기능을 제공한다.
- API Key는 평문 저장하지 않는다.
- 주문·출금 권한이 포함된 키는 등록을 거부하거나 명확히 경고한다.
- AI 요약에는 개인 식별 정보와 전체 원시 거래 원장을 보내지 않는다.

## 4. CSV 파싱 리스크

### 주요 실패 원인

- 거래소별 컬럼 차이
- 분할 체결과 주문 ID 누락
- 시간대/인코딩/천 단위 구분자
- 입출금·에어드랍·스왑의 거래 오인
- 부분 매도와 미청산 포지션

### 통제

1. 업비트 KRW 포맷을 우선 확정한다.
2. 가져오기 전 미리보기와 오류 행을 표시한다.
3. 같은 주문의 분할 체결을 병합한다.
4. FIFO 라운드트립과 수수료 분리를 테스트한다.
5. 지원하지 않는 행을 조용히 추정하지 않고 제외 사유를 보여준다.
6. 실제 익명화 샘플 파일로 회귀 테스트를 유지한다.

## 5. 스코어 신뢰 리스크

- 모든 점수는 최소 표본을 가진다.
- 표본 미달은 0점이 아니라 `측정 중`이다.
- 설문 답변은 실제 거래 기반 점수를 직접 가감하지 않는다.
- 예외적으로 사용자 선언 한도가 필요한 F8은 한도 미설정 시 실측만 표시한다.
- 외부 데이터가 없을 때는 가중치를 재정규화하거나 `준비 중`으로 표시한다.
- 계산식 버전과 분석 기준일을 저장해 재현 가능하게 한다.
- 점수 정의 변경 시 이전 점수와 직접 비교하지 않거나 재계산 버전을 명시한다.

## 6. Read-Only API 리스크

API 연동은 MVP 이후다.

- CSV 경로를 항상 대체 수단으로 유지한다.
- 거래소별 Rate Limit 큐와 캐시를 둔다.
- 모바일 클라이언트에서 상시 폴링하지 않는다.
- 권한 검증, 암호화 저장, 키 폐기 절차를 별도 설계한다.
- 주문·출금 엔드포인트는 코드와 권한 범위에서 배제한다.

## 7. PDF 처리 결정

PDF는 MVP 핵심 경로가 아니다. 텍스트형 거래내역서의 파싱 성공률과 운영 부담을 PoC로 검증한 후 지원한다. 스캔 PDF를 불완전한 OCR로 자동 해석해 점수를 만드는 것은 금지한다.

## 7.5 창업자 이해충돌·겸업 리스크

현 단계 최우선 출시 게이트다. 창업자가 거래소 이해관계자로서 자기 제품의 사용자가 될 수 없는 구조라면 dogfooding이 불가능하고, 재직사 고객 거래 데이터를 개인 서비스로 수집하는 형태는 규정 저촉 여부와 무관하게 설명이 어렵다.

통제:

1. 출시 전 사내 취업규칙·윤리강령 원문에서 `겸업`, `외부활동`, `영리행위`, `이해충돌` 조항을 확인한다.
2. PRD의 후속 지원 거래소에서 빗썸 CSV를 제거하고, 업비트·바이낸스 중심으로 검증한다.
3. 외부 사용자 표본으로만 가정을 검증한다.
4. 확인 완료 전에는 공개 출시·유료 결제·사용자 데이터 수집을 진행하지 않는다.

## 7.6 이메일 발송 리스크

주간 회고와 PDF 리포트는 즉시성이 필요하지 않으므로 이메일이 기본 채널이다. 단, 이메일은 개인정보·광고성 정보 규제가 직접 연결된다.

통제:

- 리포트 메일과 마케팅 메일의 수신 동의를 분리한다.
- 수신 거부와 삭제 경로를 메일 하단에 표시한다.
- 야간 발송은 피하고 사용자 지역 기준 업무 시간대 배치를 기본으로 한다.
- 손실 확정·드로다운 등 실시간 손실 상태를 자극하는 문구는 발송하지 않는다.

## 8. AI 사용

허용:

- 결정론적 스코어·집계 결과의 자연어 요약
- 근거 거래의 중립적 설명
- 사용자가 고른 원칙의 변화 요약

금지:

- 가격 전망과 종목 평가
- 포트폴리오 조정
- 실시간 손실 상태에서 매매 행동을 유도하는 알림
- 근거 데이터에 없는 원인 추정

AI 출력은 금지 표현 필터와 템플릿 검증을 통과해야 한다.

## 9. 출시 전 검증 게이트

- 업비트 샘플 CSV 파싱 회귀 테스트
- FIFO/수수료 골든 테스트
- F1~F10 최소 표본·예외 테스트
- 창업자 겸업·이해충돌 확인 완료
- 이메일 수신 동의/해지/리포트·마케팅 분리 검증
- 설문 건너뛰기 경로 테스트
- 데이터 삭제/내보내기 테스트
- 금지 카피 정적 검사
- iOS/Android 로컬 저장·복원 테스트
- 개인정보 처리방침과 앱 내 고지 검토

법률 자문이 필요한 출시 단계에서는 이 문서를 법적 결론으로 사용하지 않고 전문 검토의 입력 자료로 사용한다.
