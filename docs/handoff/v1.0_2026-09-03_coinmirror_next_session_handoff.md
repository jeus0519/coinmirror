## 2. 오늘까지 완료한 핵심 작업

### A. 업비트 PDF/CSV 분석 파이프라인

- 업비트 PDF/CSV 거래내역 업로드 지원.
- 거래내역을 `RawExecution`으로 변환해 공통 분석 파이프라인으로 수렴.
- CSV/PDF 모두 Phase 1 엔진으로 투자거울 타입과 F점수 산출.
- 이미지 PDF/암호화 PDF/헤더 미인식/필수 컬럼 누락 등 실패 케이스 안내 강화.
- 원본 PDF, PDF 비밀번호, 개별 체결 원문을 장기 저장하지 않는 원칙 반영.

### B. 투자거울 타입 및 행동 점수

- 투자거울 타입 코드 예: `W-R-L-N`, `?-?-?-?` 등.
- F1/F3/F6/F8 행동 점수 산출.
- 표본 부족 시 숫자를 꾸미지 않고 `측정 중` 또는 `판단 보류` 처리.
- 점수는 투자 실력/성과가 아니라 거래 행동 안정성 지표라는 카피 유지.

### C. 구독관리 local-first MVP

구현된 구독관리 핵심 축:

1. 기준선 스냅샷 저장
2. 직전 분석과 다음 업로드 비교
3. 악화 지표 기반 목표 후보 생성
4. 목표 저장/달성/재점검/판단 보류 평가
5. localStorage 기반 저장/복원/삭제
6. 원본 데이터 저장 금지 원칙

주요 파일:

```text
src/lib/subscription/snapshots.ts
src/lib/subscription/goals.ts
src/lib/subscription/persistence.ts
src/stores/use-flow-store.ts
src/components/steps/step-2-analysis.tsx
```

### D. 중복 업로드 자동 제외

구현 내용:

- `executedAt + symbol + side + price + quantity + fee` 조합을 정규화해 체결 fingerprint 생성.
- 2회차 이후 업로드에 이전 체결이 섞이면 중복 체결을 신규 집계에서 제외.
- 중복 제외 건수, 신규 반영 건수, 중복률 안내 카피 표시.

### E. 교차 기간 청산 보정

구현 내용:

- 이전 기간에 매수한 체결이 2회차 파일에 중복 포함되어 있고, 이번 기간에 매도된 경우 처리.
- 중복 매수는 신규 주문 수/체결 수에 재집계하지 않음.
- 단, FIFO 원가 연결용 context lot으로만 사용.
- 신규 매도의 승률/손익/보유기간 계산이 끊기지 않도록 보정.

결정 옵션:

| 옵션 | 설명 | 추천 상황 |
| --- | --- | --- |
| A. repo에 포함 | 지원서/이미지까지 앱 repo에서 버전관리 | 코인미러 사업화 자료를 한 repo에서 관리하려는 경우 |
| B. Obsidian/별도 사업 폴더로 이동 | 앱 코드 repo와 지원서 자산 분리 | 코드 repo를 가볍게 유지하려는 경우 |

현재 추천은 **A 또는 B를 명시적으로 결정**하는 것. 지금처럼 미추적 상태로 두면 나중에 중요한 산출물인지 임시 파일인지 헷갈릴 수 있다.
