# /review

## 절차

1. `git diff` (스테이징 여부 관계없이 전체 변경분)를 읽는다.
2. `CLAUDE.md`의 불변식 8개를 기준으로 위반 여부를 하나씩 확인한다:
   - `.env` 하드코딩/커밋 여부
   - `ios/`, `android/` 직접 수정 여부
   - 컴포넌트에서 Supabase 직접 호출 여부 (레이어 위반)
   - Reusables로 대체 가능한데 새로 만든 UI 컴포넌트
   - 화면 로컬 state를 불필요하게 Zustand로 승격했는지 (또는 반대로 넘나드는 상태를 useState로 어설프게 처리했는지)
   - 입력/응답 경계에서 검증 누락
   - RLS 없는 새 테이블, `service_role` 키 노출
   - lint/format 미통과
3. 발견한 문제를 파일:라인과 함께 나열. 심각도 순(동작 오류 > 불변식 위반 > 스타일).
4. 사소한 스타일 지적보다 실제로 깨지는 지점에 집중한다 — 트집 잡기 금지.
5. 수정은 사용자가 요청할 때만 진행한다 (리뷰와 수정을 분리).
